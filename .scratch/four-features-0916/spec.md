# Spec：四功能批次（小组件深链 / 记录合法性软提示 / 花费统计 / 加油记录+油耗）

Status: ready-for-agent

日期：2026-09-16。来源：本会话产品拍板（加油入口跟随开关、五项精简字段、统计走汇总行+独立页）+ 代码探索结论。

## Problem Statement

车主（单人使用 Lunio 记录保养）当前有四个未满足的诉求：

1. 桌面小组件点了只冷启 App，如果上次停在别的 tab 还要手动点回提醒页。
2. 补录/编辑保养记录时可能造出"时间倒回、里程反增"的矛盾历史（例如晚日期的记录里程反而更低），App 不作任何提醒，事后看数据对不上。
3. 记录页只管记，花了多少钱没有全貌：年度对比、哪些项目最花钱、月度走势都看不见。
4. 加油域只有油价预测，没有加油流水；真实百公里油耗和每公里油费算不出来，油价预测缺一个"我自己加一箱要花多少"的落地闭环。

## Solution

1. **小组件点击深链**：注册 `lunio` URL scheme，小组件声明 `widgetURL`，点击小组件（冷启或热启）都落在提醒页。冷启本来就在提醒页（默认首屏），本功能实际补的是热启回跳。
2. **记录合法性软提示**：新增/编辑记录提交第一步时，若草稿与已有记录构成"里程不随日期单调非降"，弹确认框说明冲突参照记录；用户可选"仍要继续"或"返回修改"，**不拦截保存**。
3. **保养花费统计**：记录页头部加一行可点汇总（今年花费）；完整统计放独立页，从记录页汇总行和我的页设置行两处进入。内容：总花费、今年花费、按年横条、项目占比 Top、近 12 个月走势，支持按车切换（含"全部"）。
4. **加油记录+油耗统计**：加油页（跟随现有"加油预测"开发者开关）新增第三张卡"加油记录"：五项字段记一笔（日期/里程/金额/升数/是否加满），单价自动算只读；满箱段口径计算百公里油耗与每公里油费，卡片顶部显示平均值、每行显示本段油耗；支持编辑/删除；数据进备份（v3）。

## User Stories

### 小组件深链

1. 作为车主，我想点击桌面小组件后直接看到提醒页，以便不用手动找 tab。
2. 作为车主，当 App 在后台停在记录页/我的页时，我想点小组件直接跳回提醒页，以便少点一次。
3. 作为车主，我想冷启点小组件仍然落在提醒页（现有行为保持不变），以便习惯不被打破。

### 记录合法性软提示

4. 作为车主，我想在补录一条比已有记录更早、但里程更高的记录时被提醒时间与里程矛盾，以便及时发现填错。
5. 作为车主，我想在补录一条比已有记录更晚、但里程更低的记录时被同样提醒，以便发现里程填反。
6. 作为车主，我想在编辑历史记录改出上述矛盾时也被提醒（编辑模式同样检查），以便修数据时不引入新矛盾。
7. 作为车主，我想在提示框里看到是哪条记录冲突（日期+里程），以便判断哪边填错了。
8. 作为车主，我想选择"仍要继续"强制保存（软提示不拦截），以便真实世界的乱序数据（如补录后修正）不被挡住。
9. 作为车主，我想选择"返回修改"回到第一步改日期或里程，以便顺手修正。
10. 作为车主，当数据没加载完时我想表单照常可用（检查跳过、兜底校验在保存时），以便不被加载状态卡住。

### 保养花费统计

11. 作为车主，我想在记录页一眼看到今年已花多少钱，以便对开支有直觉。
12. 作为车主，我想从记录页汇总行一键进入完整统计，以便顺着看到明细。
13. 作为车主，我想从我的页一个固定入口进统计页，以便不经过记录页也能看。
14. 作为车主，我想看到总花费和今年花费两个汇总数，以便回答"这车养到现在花了多少"。
15. 作为车主，我想看到按年的花费横条对比，以便看出逐年趋势。
16. 作为车主，我想看到花钱最多的保养项目排行（占比），以便知道钱花在哪类项目上。
17. 作为车主，我想看到近 12 个月的月度花费走势，以便判断最近养车成本是否抬头。
18. 作为车主，我想统计页默认看当前用车、也能切到其他单车或全部车辆，以便多车对比。
19. 作为车主，项目费用未填时统计按"项目费用优先、缺则材料+工时、再缺则跳过该行"的口径计算，以便占比不失真也不虚增。
20. 作为车主，记录总费用（权威值）与项目合计不一致时统计仍按记录总费用算总额，以便与 ADR 0010 的软提示模型一致。

### 加油记录+油耗

21. 作为车主，我想在加油页"记一笔"：填日期、里程、金额、升数、是否加满五项即可保存，以便 30 秒记完一次加油。
22. 作为车主，我想单价（金额÷升数）自动展示且不可改，以便不用手算也不用多填一项。
23. 作为车主，我想卡片顶部看到平均百公里油耗和每公里油费，以便掌握真实用车成本。
24. 作为车主，我想每条加油记录旁看到"本段油耗"，以便发现油耗异常的区间。
25. 作为车主，我只在"上一次加满 → 这次加满"的区间看油耗（部分加油计入升数但不闭合区间），以便油耗计算符合物理事实。
26. 作为车主，第一条加油记录（无前序满箱锚点）不显示油耗，以便不出现拍脑袋的数字。
27. 作为车主，区间里程为零或为负时该段不计油耗（折叠为空），以便乱序/同日数据不出负数油耗。
28. 作为车主，我想点记录行进入编辑（可改五项），以便填错能改。
29. 作为车主，我想在编辑里删除一条加油记录（有确认框），以便清理误记。
30. 作为车主，我想同一辆车同一天可以记两次加油，以便长途一天两箱不被拦。
31. 作为车主，加油记录列表超过一屏时默认收起只显示最近 5 条、可展开，以便加油页不无限变长。
32. 作为车主，删车时加油记录随之删除，以便不留孤儿数据。
33. 作为车主，我想备份导出/恢复包含加油记录，以便换机数据完整。
34. 作为车主，我拿旧版本（v1/v2）备份文件导入时不报错、加油记录按空处理，以便旧备份仍然可用。
35. 作为车主，还没有加油记录时卡片给一行空态文案而不是隐藏入口，以便知道功能在这。
36. 作为车主，加油记录不改变车辆档案里的当前里程（保养记录仍是唯一写源），以免两个来源打架。
37. 作为车主（开发者模式关闭时），加油 tab 整体不可见，行为与现状一致。

## Implementation Decisions

### 全局

- 遵循仓库现有分层：领域规则纯静态类、仓库事务、保存动作层（ADR 0007）收编写库+失效、UI 只留反馈薄壳。不引入新依赖（统计条自绘，无图表库）。
- 文案：加油页标题与底部导航由「加油预测」改为「加油」（新增流水后原名不准确）。

### 小组件深链

- iOS Info.plist 注册 URL scheme `lunio`；Swift 小组件根视图加一处 `widgetURL`，URL 形态必须是 `lunio:///reminders`（go_router 只匹配 path，`lunio://reminders` 的 path 为空会匹配失败）。
- Dart 路由零改动：`/reminders` 本就是 initialLocation；热启由 Flutter scene delegate 自动转发 URL 给 go_router 完成。
- 这是 ADR 0013「第一版不接深链」决定的推翻：修订 ADR 0013 追加修订记录，同步小组件 Swift 注释、AGENTS.md、CONTEXT.md 共 4 处表述。

### 记录合法性软提示

- 领域规则：`RecordRules` 新增纯函数，输入该车全量记录 + 草稿（日期/里程/自身 id），输出冲突参照记录或 null。判定：存在记录 R，使得（R 晚于草稿且 R 里程更低）或（R 早于草稿且 R 里程更高）＝里程不随日期单调非降；同日跳过（同日冲突由既有查重/唯一约束兜底）；编辑模式排除自身。
- 触发点：表单第一步「下一步」时检查，新增与编辑都查（区别于同日查重只查新增）。记录数据未就绪则跳过（保存时既有校验兜底）。
- 交互：仿同日查重确认框——标题「与已有记录不一致」，文案含参照记录日期与里程，confirm「仍要继续」放行进第二步，cancel「返回修改」留在第一步。两分支都不写库。

### 保养花费统计

- 聚合为纯函数（features 层新文件，仿记录行组装的纯函数惯例）：输入全量记录+项目清单，输出年度花费、近 12 个月走势、项目占比 Top N。
- 口径：总额/年度/月度用记录总费用（权威值，必填）；项目占比按「项目费用 ?? 材料+工时，再缺跳过」；未填不按 0 计。
- 页面：新增 pushed 子页路由 `/cost-stats`（首个非 tab 路由先例，默认转场、不挂主壳层）；顶部栏组件增加可选 leading 位放返回键；页面用现有页面骨架 slivers 版。
- 作用域：默认当前用车，顶部车辆 chips 可切单车/全部；"全部"经新增的按车记录 family provider 聚合（复用既有"按车取全量记录"仓库方法，无新 SQL）。
- 入口两处：记录页头部汇总行（今年花费+引导文案，记录非空才显示）、我的页「花费统计」设置行。
- 不动数据库：纯读取聚合。

### 加油记录+油耗

- 新表 `FuelRecords`：id、carId、date（text yyyy-MM-dd）、mileageKm（int）、volumeLiters（real，与油箱容积同精度先例）、totalCostCents（int，分）、fullTank（bool）+ sync 三列；**不设 {carId, date} 唯一约束**（同日两箱合法）；carId 普通索引。数据库 schemaVersion 2→3（ADR 0005：版本不符删库重建，无升级分支）。
- 实体 + 行↔实体编解码成对新增（遵循"一张表的字段清单全库只有一份"）。
- 校验：里程/金额非负、升数 >0；日期范围同保养记录（上路日期起，允许未来）。
- 油耗口径（满箱段，full-to-full）：记录按（日期、里程、id）升序；一条记录"闭合一段"当且仅当它加满且存在更早的满箱记录；段升数＝锚点之后至闭合条（含）的升数和；段里程＝闭合条里程−锚点里程，≤0 则该段无效（折叠，不计入均值）；首条满箱不闭合。平均油耗＝有效段升数和÷有效段里程和×100；每公里油费同理按金额。**加油记录不联动车辆当前里程**（保养记录是唯一写源，避免双写竞争）。
- 仓库：加油域仓库扩展（列表/保存/更新/删除），删车级联复用既有"主仓库借道加油仓库删行"接缝；providers 加按当前用车的加油记录派生 provider 并入车辆家族失效名单。
- 备份 v3：契约版本 2→3，接受版本 [1,2,3]；新增加油记录数组字段，v1/v2 缺字段按空读入（纯增量缺失，沿用 ADR 0010 先例）；导出补一段、恢复事务内 carId 重映射 + 引用完整性校验 + 两个清理名单（恢复清表、清空数据）都加新表。油价缓存/手填油价仍不进备份。
- UI：加油页 Column 第三张卡——头部「加油记录」+「记一笔」；摘要行（平均油耗、每公里油费，无有效段不显示）；记录行（日期+里程+升数+金额+本段油耗），默认最近 5 条、超出折叠可展开；行点按开表单 sheet（编辑态含删除+确认框）；表单五项（日期选择器、三个数字输入走统一数字输入组件、加满开关默认开）+ 单价只读行；保存走表单提交运行器 mixin + 动作层两个新函数（保存/删除，确认框留调用方）。空态一行文案。
- 新增 ADR 0014 记录：数据模型、满箱段口径、不联动车里程、DB v3、备份 v3 兼容读。

### 文档同步义务（随票执行）

AGENTS.md（DB/备份版本号、加油域描述、路由清单）、operations-manual（新交互章节）、CONTEXT.md（加油记录/加满/满箱段/油耗等词条）、migration 文档（新表+版本）、ADR 0013 修订、ADR 0014 新增、DESIGN.md（若统计页引入新视觉模式）。

## Testing Decisions

- 好测试只测外部行为：纯函数测输入→输出（含边界折叠口径）；数据层测内存库上的行为（级联、清理、往返）；widget 测用户可见行为（弹窗文案、行内容、跳转），不测内部状态。
- 三层既有接缝，零新接缝类型：
  - 领域：软提示规则、满箱段链（含部分加油、首条不闭合、里程非增折叠、均值）、花费聚合（含 null 口径）单测；核心纯函数做变异验证（仓库习惯）。
  - 数据：加油记录 CRUD、删车级联、清空数据清新表；备份 v3 round-trip、v2 兼容读（沿用 backup codec 测试的字符串替换手法）、恢复 carId 重映射。
  - Widget：加油卡记一笔/编辑/删除/折叠/摘要行；记录页汇总行与统计页渲染、入口跳转；软提示弹窗三态（弹出、仍要继续进第二步、返回修改留在第一步）。
- Prior art：记录页查重弹窗两用例（打开即弹/返回循环再查）、加油域备份往返测试、备份 codec v1 兼容读测试、widget 夹具"播种必须在装配前"约定。
- 小组件深链无自动测试面（Dart 零行为变化）：模拟器 `simctl openurl` 手动验证热启跳转；现有 widget 测试继续隐式覆盖冷启默认落提醒页。

## Out of Scope

- 加油花费并入保养花费统计（先各算各的，后续可合）。
- 年检/保险等非保养提醒类型（另一个功能轮）。
- 小组件深链定位到某个具体项目、通知点击深链（基建顺路惠及，但本轮只做小组件 → 提醒页）。
- 油耗异常诊断/修正建议、油耗与油箱容积联动提示。
- 备份文件"升级重导出"工具；v1/v2 文件不转换，只保证可读。
- Android 侧深链 intent-filter 与 Android 小组件。
- 加油站/备注字段、单价金额互算录入（按拍板取五项精简版）。
