# 方案：新增保养记录「当天已有记录」前置拦截

仅做需求 1（需求 2 不做）。拦截发生在第一步，用户不会带着重复日期进入第二步。

## 交互流程

1. **打开时检查**（仅新增模式）：表单打开后（首帧后 postFrameCallback），默认日期=生效今天，查当前车辆当天是否已有记录，有则弹窗。
2. **选完日期后检查**：日期选择器关闭后立即查所选日期，有则弹窗。
3. **弹窗**：`showConfirmDialog`，标题「该日期已有保养记录」，按钮「返回」+「去编辑」（destructive: false，确认键用主题色）。
   - **返回**：关弹窗 → 自动重开日期选择器（初始值为当前选中日期），换日期后再检查，循环。
   - **去编辑**：关新增 sheet → 打开该条记录的编辑 sheet（复用 `showMaintenanceRecordFormSheet(record: ...)`）。
4. **范围**：仅新增模式。编辑模式不改（改日期撞已有记录时仍走保存时 Repository 校验报错）。
5. 兜底：records provider 未就绪时跳过检查（不弹窗），保存时 Repository「这辆车当天已有保养记录」校验照旧兜底。

## 改动文件

1. **`lib/features/shell/records/records_page.dart`**
   - `MaintenanceRecordForm` 加 `onExitToEdit` 回调参数（`void Function(MaintenanceRecord)`），由 `showMaintenanceRecordFormSheet` 接线：pop 当前 sheet（sheetContext）→ 用外层 context 开编辑 sheet。
   - `MaintenanceRecordFormState`：
     - 新增 `_findRecordOn(LocalDate date)`：从 `ref.read(appliedCarRecordsProvider).value` 过滤同日期记录（唯一约束最多一条）。
     - `initState`：非编辑模式记标记，首帧 build 后 postFrameCallback 检查默认日期。
     - `_pickRecordDate` 改循环：选完日期 → 查重 → 有重复弹窗（返回=重开 picker，去编辑=调 `onExitToEdit`），无重复则结束。
2. **`lib/features/shell/shared/modal_feedback.dart`**
   - `showConfirmDialog` 加可选 `cancelLabel` 参数（默认「取消」，现有调用不受影响）。

## 文档义务

## 验证

1. `flutter analyze`
2. widget 测试（records 域）新增用例：打开新增表单且当天已有记录 → 弹窗出现；「去编辑」→ 新增 sheet 关、编辑 sheet 开；「返回」→ 日期选择器重开；选已有日期 → 弹窗、选无记录日期 → 不弹；编辑模式不弹。
3. 全量 `flutter test` 回归。

## 风险

- 打开时弹窗时序（postFrameCallback）在 sheet 动画期间弹出，需真机/模拟器确认观感（本机模拟器构建已恢复可用）。
- 「去编辑」跨 sheet 切换依赖外层 context 仍 mounted，沿用了现有保存成功后 toast 的同款模式，风险低。
