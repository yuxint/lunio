## 执行步骤

### 第一步：分析报告 docs/code-review-report.md

- **Java → Dart/Flutter 概念对照速查表**（附录，放报告开头）：Widget≈组件+模板、build()≈渲染函数、Future≈CompletableFuture、Riverpod Provider≈带失效机制的缓存 Bean、ref.watch/ref.read/invalidate≈依赖注入与缓存失效、Drift≈MyBatis/JPA、MethodChannel≈跨进程 RPC、setState≈局部刷新触发。
- **分层评估**：对照标准分层逐层打分，指出跨层依赖缝隙（UI 直接 import data 层 3 处、Repository 抛中文用户文案、bootstrap 依赖 Flutter services）。
- **问题清单**（按严重度排序，每条带 文件:行号 + 推理链 + 建议修法 + 「本轮未修复」标注），重点收录：
  - 恢复备份/清空数据后停车倒计时系统闹钟（id 9001/9002）残留不取消
  - 通知重调度丢更新竞态（签名先置值 + in-flight 直接丢弃）
  - 恢复备份静默清空全部偏好（主题/通知设置/snooze 记录）
  - `maintenance_records` 唯一约束 {carId,date} 与"同日不同项目可多条"业务规则冲突
  - 全局可变 `notificationSyncGeneration` 并发控制绕过 provider 体系
  - 提醒页 250ms Timer 全页重建；每次重排串行 cancel 1000 个通知 id；外键列无索引
  - `maintenanceDueEnabled` 保存时硬编码 true（用户无法关闭到期提醒）
  - 通知设置 sheet loading 期读默认值可能覆盖真实设置；iOS 文件桥注册失败无容错；monthly 调度月末漂移；停车倒计时过期不自清理等
- **复用评估**：三类分列——合理提取（showLunioModalSheet 16 处、showStatusOverlay 13 处、friendlyError 17 处等）、过度提取（单调用点却放 shared 的 LoadingPage/ErrorPage/FilterBar/ChoiceChipButton 等）、该提取未提取（RecordIntervalInputRow 与 ReminderRuleInputRow 几乎逐行重复、三套 sheet 骨架并存、_formatClock 双实现等），附引用次数统计。
- **业务逻辑合理性**：进度计算双维取大、里程只增、应用车辆回退规则等主干逻辑合理且测试扎实；列出边界缺陷（DST/时区、未来日期记录、备份恢复不校验业务规则）。

### 第二步：操作手册 docs/operations-manual.md

按用户操作路径组织，每个操作 = 操作步骤 → 代码链路（文件:行号，以方法名为主要锚点）→ 数据/偏好变化 → 涉及的通知 id。章节：

1. 冷启动与首次进入（通知初始化 → 路由 → 数据库惰性打开 → bootstrap 写入车型库与默认项目 → 无车空卡片 → 首次通知权限请求）
2. 提醒页：当前车辆卡片、切换车辆、停车倒计时（开始/展示/结束）、保养提醒列表（进度计算/排序/详情）、新增保养记录入口
3. 应用内提醒弹窗、snooze/ack 机制与偏好 key
4. 记录页：列表、筛选、两步表单（含行内新增项目、间隔更新）、删除整条/单项
5. 我的页：车辆管理（两步新增向导/编辑/切换/删除级联）、保养项目管理、备份导出/导入全链路（含原生文件桥）、清空数据、通知设置、手动日期、主题切换、开发者模式（连点 5 次）
6. 主壳层：底部导航、生命周期 resumed 行为、系统通知签名比对同步机制、通知 id 分配表（8000 系保养 / 8900 系里程 / 9001-9002 停车）
7. 手册维护规则（行号漂移处理约定：以文件+方法名为锚点）

### 第三步：分批加注释（只加注释，零行为改动）

批次顺序（先底层后上层，行号从下往上稳定）：

- **批次 1 app 装配层**：main.dart、app_router.dart、lunio_app.dart、providers.dart —— 详细注释 provider 依赖图、watch/read/invalidate 语义、惰性数据库打开。
- **批次 2 domain 层**：entities 9 个（≈DTO/POJO，注释字段业务含义与校验）+ rules 4 个（≈Service 静态方法，逐方法注释输入输出与边界，如进度计算双维取大、addMonths 月末钳制）。
- **批次 3 data 层**：app_database.dart（表结构、唯一约束、迁移链 v1→v5）、backup_codec.dart（JSON 契约）、built_in_vehicle_catalog.dart、lunio_repository.dart（1388 行，逐方法注释：事务边界、校验规则、错误语义、缓存失效责任在 UI 的约定）。
- **批次 4 core 层**：date（LocalDate/手动日期双轨机制）、id、notifications（调度全流程、错峰算法、平台差异）、platform（三个 MethodChannel 桥 + 原生侧位置）、theme、widgets。

注释风格：文件头 `///` 块（职责 + 在 App 中的位置 + Java 类比）；类与公开方法（参数/返回值/副作用：写库、失效 provider、调度通知）；关键算法行内注释；Dart/Flutter 语法概念在首次出现处用 Java 术语解释。
