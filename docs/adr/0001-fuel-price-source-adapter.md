# ADR 0001：油价数据源走适配器抽象

日期：2026-08-31
状态：已接受（2026-09-01 真源已按本决定接入，见 ADR 0006）

## 背景

加油预测功能需要外部油价数据（按省、按油品的每升价格）。但做这个功能时，真实的外部接口还没有选定（字段、鉴权、返回结构都待定）。业务侧（计算加满金额、展示价格）不能等接口，也不能绑死在某个接口上。

## 决定

1. Lunio 定义自己的油价字段契约：**省份、油品编号、每升单价、生效日期、数据更新时间**。
2. 业务代码只依赖这个契约和一个内部抽象（油价数据源接口）。
3. 第一版内置一个"示例数据源"（写死的假价格，界面不特别标注来源）。
4. 真接口确定后，只新增一个适配器实现并替换注入，业务代码与页面不动。
5. 拉到的油价缓存在本地（不进备份文件），自动更新规则：距上次成功拉取 ≥ 10 个自然日则重新拉；另有手动刷新入口。

## 后果

- 业务代码与外部接口解耦：换接口不改业务代码。
- 代价是当前存在"只有一个实现"的接口层，读者需知其原因是接口待定。
- 备份契约保持 v2 不受油价缓存影响；加油设置进备份才升 v3（见 operations-manual）。

## 备选方案

- 直接写死调用某个第三方接口：最省事，但接口一换就要改业务代码，且现在根本没有可选的接口。
- 用 WebView 抓页面数据：脆弱、体验差，放弃。

## 附注：省份知识的归属（2026-09-14 修订）

省份清单（31 个省级行政区，不含港澳台）与产品默认省"湖北"是领域/产品数据，
不随数据源走：清单是领域常量（`fuel_price.dart` 的 `fuelProvinces`），默认省由
偏好门面兜底（`LunioPreferences.defaultFuelProvince`，与油品默认 92# 同打法）。
适配器只保留自己的取数地址映射（省名 → qiyoujiage 详情页路径），"领域清单 ⊆
适配器覆盖"由覆盖守卫测试锁定（`fuel_price_source_test.dart`）。UI 与业务代码
不得 import 数据源实现类——适配器引用只允许出现在油价域注入点
（`fuel_prices.dart` 的 `fuelPriceSourceProvider`）。

本修订推翻早前"省份默认值由数据源层提供、取值范围由数据源层保证"的安排
（原 `getFuelProvince` 注释）：省份是全国油价市场的领域事实，不是某个站点的
站点事实；只有一个适配器时，把领域知识寄存在适配器 static 上等于让 UI 绕过
本 ADR 的 seam 直取实现类内部。备份导出不受影响：仍用原始读，"用户改过才有值，
没改过不带进备份"的口径保持不变。
