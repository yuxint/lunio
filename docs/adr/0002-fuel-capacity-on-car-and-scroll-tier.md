# ADR 0002：油箱容积随车存、加油页滚动定档

日期：2026-08-31
状态：已接受

## 背景

加油预测第一版（ADR 0001 同期）把油箱容积和剩余油量都放在 `fuel_predictions`
表，加油页有独立的"加油设置"卡和"剩余油量"卡。实际用下来页面元素太多：
设置好就不常改的省份/油品/容积常驻占屏，剩余油量的步进器也很少用。
用户在第二轮 UI 反馈中要求进一步压缩页面。

同时"油箱容积"本质是车的物理属性，挂在加油设置表里归属不对。

## 决定

1. **油箱容积挪到 `cars` 表**（数据库 v8）：`cars` 加列
   `tank_capacity_liters`（可空，1–999、最多四位小数），`fuel_predictions`
   删容积列。添加/编辑车辆表单提供非必填的容积输入；加油页不再有容积入口，
   没填容积时加满预估卡显示引导。
2. **旧容积数据不搬迁**：App 未上线，库里只有开发数据，产品确认直接
   `DROP COLUMN` 放弃（v7→v8 迁移只删列不拷数据）。
3. **备份保持 v3 版本号，内容形状跟着变**：车辆条目带
   `tankCapacityLiters`，`fuelPredictions` 条目只剩 `fuelPercent`。
   不做旧形状兼容（无流通中的旧 v3 文件）；动力类型改版将来升 v4 时
   在此基础上继续加字段。
4. **加油页滚动定档**：删掉剩余油量卡（默认 50%），加满预估改为全量
   档位列表（100%→0%，2% 一档共 51 档，窗口可见 5 档），整表上下滚动，
   滚动停稳后第一行所在档位就是剩余油量，自动写库；下次进入定位到
   该档在第一行。右上角返回图标滚回默认 50%（停在 50% 时置灰）。
   第一行不再标"（当前）"文字。剩余油量继续复用 `fuel_predictions.fuel_percent`
   字段，不加新列。
5. **省份/油品并入油价卡**：设置行整个删除；油价卡副标题"湖北 · 92#"
   两段各自可点弹出选择 sheet。省份列表 31 项，sheet 内部限高滚动，与其他
   sheet 高度统一；油品固定 4 项，改用一行胶囊单选（2026-08-31 用户反馈
   列表 sheet 选项下方留白，选项少时贴内容收矮更合适）。

## 后果

- 加油页从四卡（设置/剩余油量/油价/加满预估）减到两卡（油价/加满预估），
  设置入口一次点击可达。
- 容积归属正确（车的属性），但车辆表多一个业务字段，添加/编辑车辆表单
  多一个输入。
- 滚动位置成了数据录入方式：写库时机是"滚动停稳"（吸附物理对齐后），
  不是滚动过程中的每一帧；实现上用自定义 `ScrollPhysics` 做整行吸附，
  不能在 ScrollEnd 通知里再 `animateTo`（会被滚动位置静默忽略）。
- `fuel_predictions` 表只剩 `fuel_percent` 一列业务数据，将来若加更多
  每车加油设置可继续放这里。
- 备份 v3 在同一版本号下换过形状：判断备份来源不能只看版本号
  （当前无需判断，仅作历史注记）。

## 备选方案

- 容积继续存 `fuel_predictions`、只把输入入口挪到车辆表单：零迁移成本，
  但数据归属错误，将来动力类型改版还得再挪一次（被否，用户选 B）。
- v7→v8 迁移时把旧容积值拷到 `cars`：App 未上线无真实用户数据，
  拷贝代码是为不存在的数据写迁移（被否，用户确认放弃）。
- 备份升 v4：没有旧文件要兼容，升版本反而给动力类型改版添乱（被否）。
- 档位列表第一行钉死不滚、其余滚动：用户明确要"第一行也跟着滚"，
  滚动停后第一行即基准档（被否）。
- 点击档位行换基准档：用户明确"我不会点击某一行，自动把第一行设置为
  基准档"（被否）。
