# ADR 0010：保养记录项目费用——关联表三列存储、自动算可覆盖、软提示

日期：2026-09-06
状态：已接受

## 背景

保养记录此前只有记录级总费用（`costCents`）。产品要求支持按项目记费用，
并区分材料费/工时费。规则设计经过一轮推翻：

- 最初方案是"任意填两个字段反推第三个 + 锁定 + 总费用 ≥ 合计硬校验"；
- 最终改为更贴合真实场景（优惠、优惠券叠加）的模型：材料费/工时费手填
  → 都大于 0 时自动算项目费 → 可手改 → 项目费累加自动成总费用 → 可手改
  → 不一致红字黄三角纯提示、不拦截保存。

关键取舍：

1. **费用存哪**：记录-项目关联表（`maintenance_record_items`）一行 =
   一条记录 × 一个项目（唯一约束 {carId, date, itemId}），性质等同
   "订单明细行"，每行存自己的价格即可；同一个项目每次价格不同由行天然
   区分，不需要单开一张费用表。
2. **三列冗余**：项目费用虽可由材料费+工时费推出，但"项目费用为准"——
   它可以被优惠改价、可以脱离材料/工时单独填，推不出用户真实意图，必须
   落列；材料费/工时费单独保留是产品要这个维度，不是计算需要。
3. **软提示 vs 硬校验**：优惠让总费用合法地低于项目费合计，"≥ 合计"
   硬校验会拦住合法数据；不一致只说明"可能填错了"，不该禁止保存。

## 决定

1. **存储**：`maintenance_record_items` 加三个可空列
   `materialCostCents` / `laborCostCents` / `costCents`（单位分，
   null = 未填）。数据库 `schemaVersion` 1→2（ADR 0005：旧开发库下次
   启动自动删库重建，不写升级分支）。
2. **备份**：JSON `schemaVersion` 1→2，records 条目带上每项目费用；
   解码接受 v1 与 v2——本次是纯增量字段，v1 条目没有项目费用就等于
   "全部未填"，只需"缺字段按空处理"的兼容读，不属于 ADR 0005 要禁止
   的"旧字段语义变化回退"那类复杂分支；v1/v2 之外的版本仍然直接拒收。
3. **计算模型**（详细模式）：
   - 材料费、工时费纯手填，不做反推；
   - 材料 > 0 且工时 > 0 时，项目费用自动 = 两者之和；所有已填项目费用
     自动累加为记录总费用；
   - 自动值可手改；字段被手改后不再被自动覆盖；
   - 项目费用 ≠（材料+工时）（两者都 > 0 时）→ 项目费用红字 + 行黄色
     警告角标；总费用 ≠ 项目费用合计（有项目费用时）→ 总费用红字 +
     警告角标；
   - 提示无状态、纯展示、不拦截保存；保存校验只剩"合法非负数字"。
4. **权威值**：单个项目以项目费用为准（累加与详情展示都取它）；单条
   记录以总费用为准（列表与详情展示取它）。合计只用于自动回填与提示
   比对，不替代权威值。
5. **模式开关**：表单内开关，默认简洁模式，不跨会话记忆；编辑带项目
   费用的记录自动进详细模式；切回简洁只隐藏不删除费用数据。
6. **展示**：记录页两种视图的卡片整卡可点，弹出与提醒页同风格的详情
   sheet：按周期看整条记录（含所有项目费用），按项目只看该项目；都展示
   总费用。卡片上编辑/删除按钮不变。
   （后续调整：2026-09-08 起按项目弹窗删去总费用，总费用只在按周期
   弹窗展示；2026-09-09 起弹窗数据自取——弹窗自己 watch 全量记录与
   项目 provider，列表卡片不再透传 carRecords，实现在
   `record_detail_sheet.dart`。）

## 后果

- 备份契约升到 v2 但可兼容读 v1：之前导出的 v1 备份仍可导入，条目缺
  项目费用按"全部未填"读入（见决定 2）；v1/v2 之外的版本仍然拒收。
- 三列允许合法的不一致状态落库（如项目费用 120 ≠ 材料+工时 150），
  读取方（表单回显、详情弹窗）必须原样展示并按规则标提示，不允许读时
  "修正"数据。
- 求和、展示永远取项目费用/总费用字段本身，不做推导替换——"为准"规则
  保证存储与展示一一对应。
- 简洁模式看不到费用明细但数据仍在（编辑时自动进详细模式可见）；从
  记录删除项目时，该项目费用随行删除。
