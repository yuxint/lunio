# ADR 0011：油价按省抓取 qiyoujiage 详情页，缓存收成单省价表

日期：2026-09-12
状态：已接受（取代 ADR 0006 决定 3 的"全国价表缓存"）

## 背景

ADR 0006 选定 qiyoujiage 首页作数据源：一次请求拿全国 31 省价表，换省不用重新发请求。2026-09-12 用户实测发现首页数据在调价落地后**滞后多天不更新**：9-11 24 时调价后，首页表格里湖北 92# 仍是旧价 8.10、调价预告还挂在"下次油价9月11日24时调整"，而各省详情页（如 `/hubei.shtml`）当天就已更新到 8.31 且带日期戳 `2026-09-12`（陕西、内蒙古等抽查一致）。首页是聚合展示页，各省详情页才是站点的第一手更新点——首页作为数据源会让 App 在每次调价后多显示数天的旧价。

## 决定

1. `QiyouJiaFuelPriceSource` 改为按省份抓取**详情页**：`http://m.qiyoujiage.com/<路径>.shtml`，省份 → 路径的映射表（31 项，含山西 `shanxi` / 陕西 `shanxi-3` 的同音区分）由代码维护，与站点首页栏目导航核对；未知省份在发请求前抛 `FuelSourceException`。
2. `FuelPriceData` 从"全国价表"收成**单省价表**（`province` + `pricesByGrade` + `fetchedAt` + `forecast`）；`priceFor` 对省份不匹配返回 null（换省后旧缓存在失效间隙不透出旧省价）。
3. 换省后的拉取时机（用户决策 2026-09-12）：**不自动发请求**。控制器 watch 省份偏好，缓存省份与当前省份不匹配时按"暂无数据"展示，由用户点"刷新"显式拉新省价格。首次无缓存（新装/旧缓存损坏）仍自动拉取，拉取失败退回旧缓存的行为不变。
4. 解析规则沿用宽松正则（ADR 0006 决定 2），两处适配详情页结构：
   - 价格块从首页表格行改为 `<dt>湖北92号汽油</dt><dd>8.31(元)</dd>` 逐对抽取，dt 须含目标省名 + 已知油品关键词（防串页/改版误收）；
   - 预告解析先剥 script 再剥全部标签——详情页的预告日期包在 `<span>` 里、日期后紧跟 `<br/>` 才接方向金额，带着标签截句会把方向/金额截掉；剥标签后句内以句号截断。
5. 油价缓存 JSON 契约随实体变化（新增顶层 `province`、`prices` 变平铺）；缓存是临时数据不进备份，旧格式 JSON 解码抛异常 → Repository 按损坏打日志当无缓存 → 下次进页自动重新拉取，无需迁移。

## 后果

- 调价落地后 App 最多滞后一个刷新周期（10 自然日新鲜期 + 手动刷新），不再吃首页的额外滞后。
- 换省后油价卡短暂显示"暂无数据"，要用户多点一次"刷新"——换取的是换省后必拉到第一手价格，且平时请求量从全国级降到单省级。
- 省份 → URL 映射变成代码维护的第二份站点事实，站点改导航时需要同步（解析失败会以错误态暴露，不会静默出错）。
- 预告句过期未清的展示问题（ADR 0006 后果第 3 条已接受）在详情页同样存在，维持接受。
- **2026-09-12 二轮修订**：上一条不再"接受"——调价日早于当前应用日期的过期预告按无预告处理（预估块与"调价后价格"列回落占位，边界：调价在预告日 24 时，当天仍有效；预告无年份，按"离今天最近的同月日"定年）。缓存与控制器状态保真仍存站点原话，过滤只在展示侧一处做（`FuelRules.isForecastExpired` + 页面 `_effectiveForecastProvider`）；"今天"口径用 `effectiveTodayProvider`（业务日期统一约定）。

## 备选方案

- 继续抓首页（等待站点自行同步）：零改动，但每次调价后 App 要多显示数天旧价，用户已实测不可接受。
- 首页 + 详情页双抓（首页保全国表换省即切，详情页校正当前省）：请求量和复杂度都翻倍，且首页数据本身不可信，失去意义。
