# ADR 0018：提醒页分层清单——需要处理平铺量规行，正常项折叠

日期：2026-09-29
状态：**部分取代（2026-09-30 拍板修订：分层分组与折叠已移除，列表改全量平铺，见文末修订节；量规行形态与本文第 2 条继续有效）**（原型稿方案 A，成品稿经用户拍板；原型与探索记录在 `.scratch/design-pipeline/0929-app-redesign/`）

## 背景

提醒页列表（原「待关注项目」）把全部保养项目平铺成同构卡片：进度环 + 项目名 + 状态徽章 + 剩余文案。项目一多（默认模板 10 项）真正要处理的 1-2 项和大量正常项在视觉上权重相同，用户要自己扫徽章找重点。方向稿三轮迭代（换气质→换壳→体验模型）后用户选定"方案 A：分层直页"。

硬约束（用户拍板）：现有功能按钮一个不能少、不发明没有功能支撑的按钮、现有显示的数据都要显示。

## 决定

1. **分层**：`reminder_rows.dart` 新增纯函数 `splitReminderRows`——把已排序的行按状态分成两组：**需要处理**（warning/danger）与**其余**（normal）。入参沿用 `buildReminderRows` 的排序（超期>到期>百分比降序），分组只过滤不重排。
2. **提醒行形态**：进度环（环形 CustomPaint）改**横向量规**（圆角条 + 语义色填充 + 右侧百分比）；标题、状态徽章、剩余里程/时间详情行、整行点按详情 sheet 全部保留——展示数据一项不少，交互不变。
3. **折叠规则**：有需要处理项时，「其余」组默认折叠成一行「一切正常 · N 项」，点开才展开（展开态是 UI 状态，数据变化不重置）；**没有需要处理项时整组平铺**（标题「全部项目」）——此时没有要弱化的内容，全量项目本来就是主角。
4. **数据永远重算**（用户拍板）：分组完全由 `reminderRowsProvider` 最新数据驱动（provider 家族失效 + 有效今天 + 生命周期监听的既有机制），保存记录/更新里程/跨天/切页进入都会重算；新出现的急项立即进「需要处理」平铺区，永远不会被折叠藏住。折叠展开态只是 UI 偏好，不随数据重算跳变。
5. **范围**：只动提醒页列表区（`reminder_list.dart` 重写 + `reminder_page.dart` 解包 LunioSection）。hero 卡、动作行（新增保养记录/停车倒计时）、停车倒计时卡、详情 sheet、全部空态分支原样；记录/加油/我的页不动。
6. 语义色具体值同步调整（绿 #22c55e→#15803d、黄 #f59e0b→#b45309、红 #ef4444→#dc2626），独立成 ADR 0019。

## 后果

- 「需要处理」组的急项从"用户扫视找"变"页面直接给"，折叠行让正常项退后不占屏；全正常场景与旧版信息量一致。
- 折叠行内的行默认不可见——通知（系统通知/应用内弹窗/桌面小组件）仍覆盖全部项目状态，折叠只影响提醒页内布局，不产生信息盲区。
- `ReminderProgressRingPainter` 保留：停车倒计时卡仍用进度环；提醒行不再用它。
- 测试面：`test/features/reminder_rows_test.dart` 增 splitReminderRows 四用例；widget 测试（reminders_test.dart）锁 折叠/平铺/展开后详情 sheet/数据重算双向四行为。**坑**：折叠区内的行文本（如「机油」）默认不在树上，旧断言需先展开折叠行。
- 词汇表（CONTEXT.md「提醒页分层清单」节）与操作手册 2.4 节同步。

## 备选方案

- **方向 B（到期视野带）**：把时间维剩余天数画成 0-90 天横轴。信息视角更全局，但用户在 A/B/C 三稿中选定 A；B 的可视化可日后作为增强单独再做。
- **正常项不折叠（只分组不加折叠）**：信息零隐藏，但项目多时"需要处理"组的突出效果被下面的长列表稀释，分层失去意义——折叠是方案 A 的核心价值。
- **焦点卡方案（上轮方向三）**：整页只留最急一项、其余进底部抽屉。层级变化最大，但详情 sheet 首层内容与列表行为重叠，用户未选。

## 修订（2026-09-30 用户拍板，2026-10-01 落地）：去分层，全量平铺

用户拍板**去掉提醒页的分组显示**：不再分「需要处理 / 其余」两层，没有「一切正常 · N 项」折叠行，也没有「需要处理 · N」「全部项目」节头——全部项目按紧迫度（状态差 → 百分比降序 → sortOrder，`buildReminderRows` 既有排序）直接平铺。理由：分层折叠在真机使用中不抵其复杂度，用户要一眼看全所有项目。

- `splitReminderRows` 纯函数与 `ReminderRowGroups` 类型整体删除（无其他消费者）；`ReminderList` 从 StatefulWidget（持折叠 UI 态）简化为 StatelessWidget。
- **本文继续有效的部分**：第 2 条量规行形态（横向量规 + 徽章 + 百分比 + 详情行 + 整行点按详情 sheet）、第 4 条"数据永远重算"（排序与行状态仍由 provider 最新数据驱动）、第 6 条语义色（ADR 0019）。
- 通知侧（系统通知/应用内弹窗/桌面小组件）不受影响——它们从不依赖提醒页的分组展示。
- 测试面：`reminder_rows_test.dart` 删 splitReminderRows 四用例；`reminders_test.dart` 折叠/展开用例改写为平铺断言（急项与正常项同列表可见、无节头、保存后行状态即时翻转）。
