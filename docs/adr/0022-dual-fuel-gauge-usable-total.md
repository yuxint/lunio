# ADR 0022：双油量口径——加满可加油量、总容积与储备油量

日期：2026-11-15
状态：已接受

## 背景

思域实车 `012F` 油量 23.1% 时：

- 按官方 47 L 总容积换算约 10.87 L；
- 车辆表单填 40.487 L 时换算约 9.4 L；
- 40.487 L 是用户按智导互联百分比与多次跳枪反推的"可加油量"，
  现有加油页的"当前油量/可加油量"用它，已多次与跳枪数据对上；
- 浮子到 0% 时仪表续航 0 km，但油箱仍有约 6.5–7 L 储备；
  47 − 40.487 = 6.513 L。

用户要两个指标：日常使用的可用油量，以及含储备的真实油量。
浮子百分比是位置不是体积，任何升数都是估算。

## 关键取舍

- **把现有字段当总容积还是可用容积**：现有 `tankCapacityLiters`
  已被加油页跳枪数据验证为 40.487 的可用容积口径；改成总容积会破
  坏已验证的加满预估。决定保留其语义（UI 标签改"加满可加油量"），
  另加总容积字段。
- **储备油量 vs 总容积**：官方 47 L 是稳定事实；储备 6.513 L 是
  推导值。存总容积 47，储备由减法得出；总容积缺失时只显示可用
  油量。
- **两指标 vs 三指标**：仪表百分比是原始读数，可用/总油量是两个
  换算指标。页面显示百分比 + 一行两个升数，不把储备单独列成第三
  个数字。

## 决定

1. `cars.tankCapacityLiters` 语义 = **加满可加油量（可用容积）**，
   0%→100% 的加油量；UI 标签改"加满可加油量"，加油页与
   `FuelRules` 不改。
2. `cars` 新增 `totalTankCapacityLiters`（可空，单位升）：
   **油箱总容积**；校验 1–999、最多四位小数，且不得小于可用容积；
   未填不显示总油量。
3. 词汇：**仪表油量** = `012F` 百分比；**可用油量** = 仪表% ×
   可用容积；**储备油量** = 总容积 − 可用容积；**估算总油量** =
   储备油量 + 可用油量。0% 时估算总油量 = 储备油量，100% 时 =
   总容积。
4. 诊断页油量卡：大字百分比 + 一行"可用 x L · 估算总油量 y L"；
   总容积未填只显"≈ x L"。加油页不显示总油量。
5. **线性假设**：浮子 0–100% 与可用容积线性对应；实际油位传感器
   非线性，升数是估算。需要更高精度时另做标定表，不在本轮。
6. **私有 DID 227029**：OBDb `CIVIC_FLV`（`DA60` + `227029`，
   bit 96 / 16 位 / ÷100）是实测总油量的候选源；在加满与低油位
   两点标定前不采信。验证通过后油量卡显示"实测总油量"并保留可用
   行；失败则回落储备模型。内置油量检测点保持 `012F` 不改。

## 后果

- DB v6 / 备份 v5；车辆表单新增字段；AGENTS/手册/词汇表同步。
- 加油页、加油记录、费用统计口径不变；总容积字段不受影响。
- "真实油量"改称"估算总油量"；私有 DID 验证通过后才用"实测总
  油量"。

## 修订（2026-11-16）：227029 三点标定定案

2026-11-16 全量采集（`docs/car_obd_link/docs/全量采集分析-2026-11-16.md`）
后定案：`227029` 是**表显刻度交叉验证源，不是实际总油量**。

- 四个标定点（表显 37.65% / 23.14% / 14.90% / 74.51%）的槽位候选
  全部与 "表显 × 47 L"吻合（±5% 内），与储备模型实际值差 3–5 L。
- 四点回归：候选 ≈ 0.99 × 表显升 + 0.44（r² ≈ 0.999），外推 0% ≈
  0.4 L、满刻度 ≈ 47.0 L（2026-11-16 晚第四点收紧，结论不变）。
- 空箱（表显 0%）标定点**不做**：用户拍板不把油跑到低油位；回归
  外推已足够支撑定案，满箱点（下次加油时顺手采集）只精化斜率、
  不翻案。
- 决定 6 作废：`227029` 不接产品卡片，不显示"实测总油量"；估算总
  油量维持储备模型（决定 3/4 不变）。`227029` 保留在一键检测脚本
  里，只作满箱标定与交叉验证数据源。
