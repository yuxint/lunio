# ADR 0023：诊断刷新规则、调试终端与私有 DID 验证

日期：2026-11-15
状态：已接受

## 背景

- 现状：一轮串行发所有启用检测点，轮间隔 3 秒；没有手动刷新；页
  面不显示"无数据"的原因；没有原始响应视图。
- 实车日志的 `0100` 位图（三个 ECU）都没有 PID 05 支持位，标准
  `0105` 返回"无数据"很可能不是解析 bug，而是该车不支持标准水
  温；CarScanner 的 37/24 ℃ 更像本田私有数据。
- OBDb signalset 已确认：`227029`（`DA60`，bit 96 / 16 位 /
  ÷100，升）、`22202C`（`DA01`，四路 ECT / ÷10 ℃）、`22267A`
  等私有命令；实车多帧响应存在，但偏移/缩放未标定。
- 用户要在 App 内调试，不再用 nRF Connect。

## 决定

1. **刷新规则**：每个检测点独立 `refresh_interval_seconds`，默认
   30 秒，范围 5–3600 秒；轮询按各条到期时间调度；手动刷新立即
   轮询全部启用项；调试终端打开时暂停自动轮询。
2. **调试终端**：诊断页新增"调试"区，支持任意 AT/PID 命令、设置/
   恢复 29-bit 头、显示每条原始响应行与时间戳、复制/保存文本；命
   令与自动轮询共用同一串行链路；退出恢复 `ATSH DB 33 F1` 并重启
   轮询。
3. **一键验证脚本**：固定顺序采集 `ATI`、`ATDPN`、
   `0100/0120/0140/0160`、`0105/012F/0142/010C/ATRV`、
   `ATSH DA 60 F1` + `227029`、`ATSH DA 10 F1` +
   `222623/222678/22267A`、`ATSH DA 01 F1` + `22202C`，最后
   恢复 `ATSH DB 33 F1`。日志带时间戳与原始行，用户导出后分析。
4. **验证先行**：私有 DID 本轮只在调试/验证里用，不进正常轮询；
   内置水温保持 `0105` 并显示"无数据"原因。验证通过后再加
   `header` + ISO-TP 多帧重组 + 私有解析类型，替换内置水温或新增
   实测油量检测点。
5. **安全边界**：终端显示状态变更警告（ATSH/ATSP/ATCRA/ATD/ATZ、
   mode 04 清码等），不逐条拦截；退出恢复默认头并重启轮询，失败
   提供重连。

## 后果

- 会话决策体增加调度器、手动刷新、暂停/恢复、原始命令 API；解析
  器增加标准模板解析类型与（Phase 2）多帧重组。
- 诊断页增加调试区、无数据原因、手动刷新按钮；检测点管理 sheet
  增加刷新间隔。
- 真机验证依赖用户执行一键脚本并导日志；Phase 2 的私有 DID 上
  线以标定结果为准。
- ADR 0020 的"轮间隔为常量（默认 3 秒）"被本 ADR 的每检测点间隔
  取代。
