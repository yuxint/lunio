# ADR 0023：诊断刷新规则、调试终端与私有 DID 验证

日期：2026-11-15
状态：已接受

## 背景

- 现状：一轮串行发所有启用检测点，轮间隔 3 秒；没有手动刷新；页
  面不显示"无数据"的原因；没有原始响应视图。
- 实车日志的 `0100` 位图（三个 ECU）都没有 PID 05 支持位，标准
  `0105` 返回"无数据"很可能不是解析 bug，而是该车不支持标准水
  温；CarScanner 的 37/24 ℃ 更像本田私有数据。
- OBDb signalset 已确认：`227029`（`DA60`，bit 96 / 16 位 /
  ÷100，升）、`22202C`（`DA01`，四路 ECT / ÷10 ℃）、`22267A`
  等私有命令；实车多帧响应存在，但偏移/缩放未标定。
- 用户要在 App 内调试，不再用 nRF Connect。

## 决定

1. **刷新规则**：每个检测点独立 `refresh_interval_seconds`，默认
   30 秒，范围 5–3600 秒；轮询按各条到期时间调度；手动刷新立即
   轮询全部启用项；调试终端打开时暂停自动轮询。
2. **调试终端**：诊断页新增"调试"区，支持任意 AT/PID 命令、设置/
   恢复 29-bit 头、显示每条原始响应行与时间戳、复制/保存文本；命
   令与自动轮询共用同一串行链路；退出恢复 `ATSH DB 33 F1` 并重启
   轮询。
3. **一键全量采集**：先读 `ATI/ATDPN/ATRV`，再读本车
   `0100/0120/0140/0160/0180/01A0/01C0/01E0` 能力位图 +
   `0900/0600` 位图，按位图自动枚举所有支持的标准 PID（不靠猜清单）；
   再读 DTC `03/07/0A`；私有 DID 按 OBDb Honda Civic 2022
   `supported_commands_by_ecu` 清单（126 条，`DA10/DA11/DA1E/DA28/
   DA53/DA60` 分组，含 `227029`/`222623`/`222678`/`22267A` 等；
   北美数据，实车可能不同）逐组设置 `ATSH`；最后恢复
   `ATSH DB 33 F1`。日志带时间戳与原始行，用户导出后分析。
   2026-11-15 实车日志已确认本车 `0100` 位图无 `05/0F/10`，
   因此标准模板的进气温度 `010F` 改为支持的进气压力 `010B`；
   `22202C`（2023+ ECT）与 `2223E2/E3` 不在 2022 支持清单/实车
   返回 `7F 22 31`，不纳入自动清单。
4. **验证先行**：私有 DID 本轮只在调试/验证里用，不进正常轮询；
   内置水温保持 `0105` 并显示"无数据"原因。验证通过后再加
   `header` + ISO-TP 多帧重组 + 私有解析类型，替换内置水温或新增
   实测油量检测点。
5. **安全边界**：终端显示状态变更警告（ATSH/ATSP/ATCRA/ATD/ATZ、
   mode 04 清码等），不逐条拦截；退出恢复默认头并重启轮询，失败
   提供重连。

## 后果

- 会话决策体增加调度器、手动刷新、暂停/恢复、原始命令 API；解析
  器增加标准模板解析类型与（Phase 2）多帧重组。
- 诊断页增加调试区、无数据原因、手动刷新按钮；检测点管理 sheet
  增加刷新间隔。
- 真机验证依赖用户执行一键全量采集并导日志；Phase 2 的私有 DID
  上线以标定结果为准。
- 命令来源是可追溯的：标准 PID 来自本车能力位图；私有 DID 来自
  OBDb 2022 支持清单（源文件见 `obd_verification_commands.dart`
  文件头）与 `docs/car_obd_link/` 实车日志。
- ADR 0020 的"轮间隔为常量（默认 3 秒）"被本 ADR 的每检测点间隔
  取代。

## 修订节五（2026-11-21）：默认刷新间隔 10 → 60 秒 + 油量窗口聚合

用户拍板：油量 60 秒一拍，连续几拍在浮动范围内才更新信息卡；其他检测点
也统一 60 秒。原始日志不变。

1. **默认间隔 60 秒**（`DiagnosticsRepository.defaultRefreshIntervalSeconds`）：
   油量浮子晃动是主要噪声源，放慢采样 + 连拍聚合比高频采样更可信；7 条
   探针的总线占空比从 ~7.5% 降到 ~1.2%。实体/表单/备份缺省值同步改 60。
2. **存量迁移**：v6→v7 的 schema 迁移（`app_database.dart` 的 onUpgrade）
   把内置行的 `refresh_interval_seconds ∈ {10, 30}` 迁到 60——10 是
   2026-11-17~11-21 的默认，30 是更早的默认（v6 迁移与初版种子都写 30），
   只认 10 会漏掉 11-18 之前创建的车。自定义行不碰。
   **迁移放 schema 而非 bootstrap 对账**（2026-11-21 深审修正）：对账每次
   冷启动都跑，用户之后手选 10/30 会被静默改回；schema 迁移只跑一次，
   事后用户改动稳定生效（ADR 0021 修订节「只补缺失、不纠偏用户编辑」）。
3. **代价与补偿**：暖机期水温 0.1–0.3℃/s，60 秒一拍每次会跳 6–18℃；诊断页
   进入时可能显示最多一分钟前的值，所以页面 `initState` 的 post-frame 补
   一次 `requestImmediatePoll`（已连接复用路径不再复位倒计时）。
4. **油量门限改为窗口聚合**（`FuelLevelGate`，见 ADR 0029 修订节四补记与
   同日二次修订）：3 拍极差 ≤5 个点**且三拍严格全在卡片一侧** → 卡片取
   窗口中位数；否则保持并在会话日志记 `fuel_gate` 行。放弃「偏离基准 +
   同向连拍」判据（会被晃动下降沿锁死）。**手动刷新是例外**：用户点
   「立即刷新」要的是当前状态，直显原始值、不过门限；自动轮询、进页面
   补的那次、回前台补的那次仍走门限。手动放行旗只在**下一拍油量事件**
   消费（NO DATA/超时也算一拍，避免漏到下一轮自动轮询），断开/重连即清
   （2026-11-21 深审修正）。

## 修订节六（2026-11-21）：会话日志改记原始帧；227060 撤除；222301 一帧三量

由 11-21 早间一键检测与轮询日志对照触发。

1. **会话日志改记原始帧**（用户拍板「日志要原始的，不要解析好的」）：
   此前读数行只记解析后的展示文本（`"v":"95℃"`），与一键检测段的原始
   hex 并存于同一文件，两种口径无法互查。改法：
   - `Elm327ProbeReading` 携带 `frameText`（提示符前完整帧）与 `header`
     （当时生效的寻址头），controller 原样转交 sink；
   - 读数行加 `raw`（完整帧，多行 `0:` 行号原样，仅 CR/CRLF 归一为 LF）
     与 `hdr`；超时无帧不写 `raw`，NO DATA 原文照记；
   - 调试终端手发的每条命令另记 `{"t":"e","e":"raw"}` 行（成功 `resp`、
     失败 `err`）——这类往返此前完全不落盘，扩展会话实验无法复盘；
   - 一键检测的 ~30 条往返不逐条写（整段已在 `verify` 行），执行器传
     `sendRawCommand(logExchange: false)` 抑制。

   **为什么保留行号而不归一成单行 hex**：实车出现过 37 字节的残缺
   222301 帧（正常 41），三个字段同时错（转速 1351 vs 实测 756、水温
   90 vs 66、CVT 76 vs 25）。帧完整性只能靠行数识别，归一化会抹掉这个
   信号。解析值不是权威值，只是原始字节的一种解读。

2. **227060 撤除**：11-18、11-19（两次）、11-21 共四次一键检测恒回
   `7F 22 31`，与 222666 同一条 NRC；同段其余四条每次都正常返回，排除
   会话问题。仪表段从五条降到四条。⚠ 此前
   `一键检测候选DID验证-2026-11-18.md` 的建议是「保留以留档证明本车不
   支持」——本次推翻该建议：留档价值已由四次日志与本文承担，继续每轮
   多发一条恒定否定响应没有新信息。

3. **222301 一帧三量**（2026-11-21 交叉验证，**只入日志、不改解析类型、
   不加卡**）：
   | 字节（数据区 0 基） | 含义 | 验证 |
   |---|---|---|
   | 第 7–8 字节 | 转速 rpm | 与 010C 三次比对差 0/1/8 rpm |
   | 第 20 字节 −40 | 水温 ℃ | 与 0167 比对差 0/1℃ |
   | 第 26 字节 −40 | CVT 油温 ℃ | 卡片已用（ADR 0029） |

   不合并的理由：删除 0167 只省约 89ms/分钟（同一轮 5 条命令 556ms，
   0167 是最便宜的一条、222301 是最贵的 225ms），代价却是共模失败——
   222301 坏帧时水温和 CVT 一起错，且失去发现坏帧的独立参照（本次正是
   靠 0167 才发现 07:31 帧是坏的）。转速不进卡：60 秒一拍的转速表没有
   使用价值，进 `raw` 后离线可取。
