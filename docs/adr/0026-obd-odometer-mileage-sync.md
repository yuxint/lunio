# ADR 0026：OBD 里程表与车辆里程同步

日期：2026-11-16
状态：已接受

## 背景

2026-11-16 全量采集日志发现标准 PID `01A6` 是本车支持的里程表
（`41 A6 00 0A 14 C8` → ÷10 = 66,068 km，与 CarScanner 里程互证，
见 `docs/car_obd_link/docs/全量采集分析-2026-11-16.md`）。推荐模板
新增「里程表」探针（`01A6`，解析类型 `odometer`，4 数据字节 ÷10 km）。

车辆里程（`cars.current_mileage_km`）的现行唯一写源是保养记录
（记录里程同步走 max 守卫）。01A6 读数让它有了第二个写源，规则变化
需要记录。

## 关键取舍

- **静默自动写 vs 确认式**：静默自动写打破「保养记录是车辆里程唯一
  写源」的表述，写点隐蔽；确认式保守但每车每次都要点。拍板：**两档
  并存**，由开关切换，默认保守档。
- **守卫位置**：只增不减守卫收在动作层单点
  （`syncCarMileageFromEcu`），确认式与静默档共用同一写点，页面入口
  只管显隐。

## 决定

1. 推荐模板新增「里程表」：`01A6`，解析类型 `odometer`
   （wire `odometer`，4 数据字节 ÷10 km，千分位展示）。
2. **车辆里程第二写源**：ECU 里程可写入 `cars.current_mileage_km`，
   守卫「只增不减」（ECU 值不大于当前里程即不写）收在动作层
   `syncCarMileageFromEcu`，复用 `updateCar`（写库 + 逐出车辆族
   provider；里程变化进应用车辆数据束，提醒链自动重排）。
3. **两档行为，开关切换**：
   - 开关关（默认）= 确认式：ECU 里程 > 车辆里程时，里程表探针行内
     显「更新里程」入口，确认框两值对照后写入。
   - 开关开 = 静默自动写：轮询收到更大 ECU 里程直接写入，无 toast、
     失败降级不提示，下一轮再试。
4. 开关「ECU 里程自动同步」在检测点管理 sheet（页面级行开关）；偏好
   key `obdOdometerAutoSync`，默认关；不进备份（备份本就不带任何
   偏好），恢复备份后回落默认关。
5. 静默同步只挂探针轮询路径（controller 的 `onOdometerReading` 接
   缝）；一键检测读到的里程只显示、不写库。
6. ECU 换件导致里程变小：守卫挡住不写；用户走「我的」页 hero 卡手
   动路径调整（该路径不受本守卫约束）。

## 后果

- 解析类型 wire 词表新增 `coolantTempAux` 与 `odometer` 两个值：
  v5 备份 JSON 的 parseType 字段词汇表扩展——旧版本 App 读新备份会
  在未知 wire 值上 fail-fast（单用户场景无降级读取路径，接受）。
- DB schemaVersion 不变（无表结构变更）。
- 车辆里程出现第二写源：AGENTS「保养记录是车辆里程的唯一写源」表述
  同步修订（加油记录不联动里程的规则不变）。
- GLOSSARY 新增「里程表（ECU）」词条；手册 5.10、AGENTS、iteration
  plan 同步。
- 真机待验：0167 熄火/冷车行为、01A6 同步两档、精简后一键检测。
