## 修复详情

### 1. 备份引用错误未按类型化错误上抛

- 位置：`lib/data/repositories/backup_repository.dart:399`
- 症状：恢复一份记录引用了不存在车辆的备份时，恢复 UI 显示
  「恢复失败：Invalid argument(s): Backup maintenance record references missing car」，
  而不是「备份文件中存在无效数据（…）」。
- 证据级别：已复现（`test/data/backup_restore_test.dart` 三条引用完整性用例先红后绿）。
- 触发路径：手编/损坏的备份 JSON 通过 `BackupCodec.decode`（只做结构解码，不校验 id 引用）→
  `restoreBackupPayload` 调 `_validateBackupReferences` → 裸 `throw ArgumentError('Backup ...')`
  → `profile_page.dart` 的 `_restoreBackup` 只在 `LunioErrorException` 分支弹中文对话框，
  其余异常落到 `showStatusOverlay('恢复失败：$error')`。
- 根因：`_validateBackupReferences` 与 `_validateBackupBusinessRules` 是同一类「备份无效」，
  但前者没有走 ADR 0009 修订节规定的统一出口 `LunioErrorException(backupInvalidData)`。
- 修复：把检查体拆到 `_ensureBackupReferences`（仍抛裸 `ArgumentError`），入口
  `_validateBackupReferences` 统一 `try/on ArgumentError` 包装为 typed 错误，
  文案前缀「备份文件中存在无效数据（引用完整性）：」。预校验仍在事务外，
  「恢复失败不写入任何数据」不变。
- 回归：`flutter test test/data/backup_restore_test.dart` 18 用例全部通过。
- 提交：00bae3f

### 2. 备份检测点 carId 引用未预校验

- 位置：`lib/data/repositories/backup_repository.dart:412`
- 症状：备份 v5 的自定义检测点 `carId` 指向不存在的车辆时，错误不在恢复前被拒绝，
  而是拖到恢复事务内 `carIdMap` 重映射时才抛裸 `ArgumentError`；事务会回滚，
  但错误类型已越过事务边界，UI 同样显示英文泛化错误。
- 证据级别：已复现（新增用例
  `backup restore rejects diagnostics probe referencing missing car` 先红后绿）。
- 触发路径：备份 JSON 的 `diagnosticsProbes[].carId` 改成不存在的 id →
  `_validateBackupReferences` 只查车/项目/记录/加油预测/加油记录五类引用 →
  进入事务、清空可恢复表 → 重插检测点时 `carIdMap[probe.carId]` 为 null → 抛错回滚。
- 根因：引用完整性预校验漏了检测点段；`DiagnosticsProbe.validate()` 也只校验名称、
  指令、间隔、寻址头，不校验 carId（carId 为非空 int）。
- 修复：`_ensureBackupReferences` 末尾补检测点 carId 存在性检查，抛中文
  `ArgumentError('检测点「…」引用了不存在的车辆')`，由第 1 条的包装器统一转成
  typed `backupInvalidData`。失败仍发生在开事务之前。
- 回归：`flutter test test/data/backup_restore_test.dart` 18 用例全部通过。
- 提交：0ce80d4

### 3. 会话日志恰好 7 天时不计入 50 个文件上限

- 位置：`lib/features/shell/diagnostics/obd_session_log.dart:140`
- 症状：`ObdSessionLogStore.cleanup` 的保留策略写明「7 天 + 50 个文件双上限、删最旧」，
  但开始时刻恰好等于 `now - 7 天` 的文件既不被 7 天规则删除（`isBefore(cutoff)` 不含等号），
  也不进入 50 上限计数（`isAfter(cutoff)` 不含等号），文件总数可停在 51。
- 证据级别：已复现（新增边界用例：cutoff 文件 1 个 + 严格晚于 cutoff 的文件 50 个 →
  修复前删除 0 剩 51，修复后删除 1 剩 50）。
- 触发路径：会话日志保留窗口跨过某个整点/整秒后，恰好落在 7 天边界的那份文件在每次
  清理时都落到两个集合之外；后续新增会话只能挤掉别的旧文件，上限不变量失效。
- 根因：删除集合与计数集合不互补——一个用 `isBefore`、一个用 `isAfter`，等号时刻无人认领。
- 修复：50 上限候选改为 `!startedAt.isBefore(cutoff)`（含等号），与 7 天删除条件互补；
  「恰好 7 天算未过期」的语义不变，同时保证它计入文件数上限。`cleanup` 文档补边界说明。
- 回归：`flutter test test/features/obd_session_log_test.dart` 14 用例全部通过。
- 提交：f796f01
