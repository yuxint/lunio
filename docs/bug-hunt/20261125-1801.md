## 详情

### 1. 备份恢复不校验油箱总容积

- 位置：`lib/data/repositories/backup_repository.dart:485`
- 症状：恢复一份把「油箱总容积」改成 47 L、可用容积 60 L 的备份会成功落库，
  得到一个违反 ADR 0022（总容积不得小于可用容积）的车辆。
- 错误依据：手工新增/编辑车辆都调用 `FuelRules.validateTankCapacity` +
  `FuelRules.validateTotalTankCapacity`（`lunio_repository.dart:82`、`:126`）；
  备份业务规则注释写明「与手工录入走同一套规则」。ADR 0022 规定总容积
  1–999 L、最多四位小数且不得小于可用容积。
- 证据级别：已复现（数据层用例先红后绿）。
- 触发路径：裸插一辆 `tankCapacityLiters: 60, totalTankCapacityLiters: 47` 的车
  （绕过表单/仓库校验，模拟被篡改或旧版本导出的备份）→ 导出 payload →
  `restoreBackupPayload` → 车辆校验只查可用容积（60 合法）→ 事务清库重插，
  非法总容积进库。
- 复现：`flutter test test/data/backup_restore_test.dart --plain-name 'total tank capacity smaller'`
  — 修复前：`Expected: throws <LunioErrorException...> / Actual: returned a Future that emitted <null>`
  （恢复成功）；修复后通过。
- 根因：`_validateBackupBusinessRules` 的车辆循环只调了 `validateTankCapacity`，
  漏掉总容积及交叉字段校验。
- 修复：车辆循环补 `FuelRules.validateTotalTankCapacity(totalTankCapacityLiters,
  usableCapacityLiters: tankCapacityLiters)`，仍包在原有
  `try/on ArgumentError → LunioErrorException(backupInvalidData)` 里，失败发生在
  开事务之前。
- 回归：`flutter test test/data/backup_restore_test.dart` 19 用例全部通过。
- 提交：5af85ba

### 2. 不支持的备份版本向用户暴露英文异常

- 位置：`lib/features/shell/profile/profile_page.dart:234`
- 症状：选一个 `schemaVersion` 不受支持的备份文件，恢复页显示
  「恢复失败：Unsupported operation: Unsupported backup schemaVersion: 99」，
  英文原始异常直接给到用户。
- 错误依据：`lib/data/backup/backup_codec.dart:153` 的 `decode` 注释写明
  「其他版本抛 UnsupportedError，UI 提示『不支持的备份文件』（ADR 0005）」；
  当前 UI 没有该文案。
- 证据级别：已复现（widget 用例先红后绿）。
- 触发路径：我的页「恢复数据」→ 确认 → 选文件返回 `{"schemaVersion": 99}` →
  `decodeBackupJson` 抛 `UnsupportedError` → `_restoreBackup` 只按
  `LunioErrorException` 分支处理 → 其余落到 `showStatusOverlay('恢复失败：$error')`。
- 复现：`flutter test test/widget/settings_test.dart --plain-name 'unsupported version'`
  — 修复前 `find.text('恢复失败')` 找不到（只有一条含英文的 toast）；修复后通过。
- 根因：恢复失败分类漏了「版本拒绝」这一类预期失败。
- 修复：`_restoreBackup` 增加 `UnsupportedError` 分支，弹对话框
  「不支持的备份文件\n本次恢复未写入任何数据。」；同步更新方法注释与
  `docs/operations-manual.md` 5.4 的失败分支清单。
- 回归：`flutter test test/widget/settings_test.dart` 19 用例全部通过。
- 提交：274e32f

### 3. 清空数据后 OBD 连接仍空转轮询

- 位置：`lib/features/shell/shared/shell_actions.dart:566`
- 症状：连接 OBD 后回到「我的」页执行「清空数据」：偏好表被删，
  `diagnosticsEnabled` 回到默认关、`lastObdDeviceId` 清空，提醒页按钮/信息卡
  和诊断入口全部隐藏；但 App 级 OBD 会话没有断开，继续按旧作用域轮询
  油量/水温，且设备记忆已删、用户无法从 UI 察觉。
- 错误依据：`setDiagnosticsEnabled` 的注释与 ADR 0027——诊断开关关闭必须断开
  App 级连接，「连接不留给无人消费的空转轮询」；清空数据删除该偏好等价于
  开关回到关。
- 证据级别：已复现（widget 用例先红后绿）。
- 触发路径：种子诊断开关 + 设备记忆 → 诊断页自动连接（mock 链路）→
  离页连接保持（ADR 0027）→ 我的页「清空」→ 确认 → 偏好删除、连接仍在。
- 复现：`flutter test test/widget/diagnostics_test.dart --plain-name '清空数据断开'`
  — 修复前 `expect(rig.mock.disconnectCalls, 1)` 实际 `0`；修复后通过。
- 根因：清空数据动作层只编排了通知/实时活动/通知清扫，没有走
  `disconnectManually`；连接生命周期与偏好删除两条链没有接上。
- 修复：`clearAllData` 在 `runAllDataClear` 之后、全量 invalidate 之前调用
  `obdConnectionControllerProvider.disconnectManually()`（与设置页关开关同一
  语义）；同步更新 `docs/operations-manual.md` 5.5 流程与动作层注释。
- 回归：`flutter test test/widget/diagnostics_test.dart` 27 用例、
  `flutter test test/widget/parking_test.dart` 11 用例全部通过（后者覆盖清空
  数据的通知/实时活动清扫旧路径）。
- 提交：310bcfb
