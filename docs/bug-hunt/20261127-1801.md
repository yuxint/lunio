### 1. 建车播种检测点失败导致建车报错

- 位置：`lib/features/shell/shared/shell_actions.dart:65`
- 症状：建车事务成功后，`seedBuiltInProbesForCar` 抛错会让 `createCar` 整体
  上抛；车辆已入库，但表单显示「操作失败，请稍后重试」、sheet 留在屏幕上，
  车辆数据纪元也没有 bump，列表不刷新。用户重试「保存车辆」会再建一辆重复车。
- 错误依据：同函数注释明确「失败由 bootstrap 兜底补种，不让建车本身回滚」；
  但播种调用没有 try/catch，且 `ref.read(vehicleDataEpochProvider.notifier).bump()`
  排在播种之后，注释承诺的行为与代码相反。仓库装配里 `ensureProbes` 的
  bootstrap 对账确实是兜底路径（`built_in_catalog_repository.dart`），说明
  「播种失败可恢复」是既有设计。
- 证据级别：已复现（widget 用例先红后绿）。
- 触发路径：用注入的 `DiagnosticsRepository` 替身让
  `seedBuiltInProbesForCar` 抛 `StateError` → 向导走完「下一步 → 保存车辆」→
  建车事务成功、播种失败。
- 复现：`flutter test test/widget/vehicles_test.dart --plain-name 'add car keeps the car when probe seeding fails'`
  — 修复前断言「车辆已保存」失败（实际是表单错误、sheet 未关）；修复后通过。
- 根因：把「建车事务成功」与「附加播种成功」绑成了同一个 Future，附加步骤
  失败回滚了 UI 的成功语义。
- 修复：播种调用包 `try/catch`，失败 `debugPrint` 后继续
  `invalidate(diagnosticsProbesProvider)` 与车辆数据纪元 bump；检测点由
  bootstrap 按车补缺失。无新增状态，不改播种接口。
- 回归：`flutter test test/widget/vehicles_test.dart` 15 用例全部通过。
- 文档：`docs/operations-manual.md` 421 行补「播种失败不阻断建车，由 bootstrap
  兜底」。
- 提交：4391b56

### 2. 删除最后一辆车后 OBD 连接空转

- 位置：`lib/features/shell/shared/shell_actions.dart:83`
- 症状：连接过 OBD 后删掉唯一一辆车，App 级诊断连接仍然保持「已连接」并继续
  轮询；检测点已随车级联删除，提醒页不再有车辆可服务、也不会再推送轮询清单，
  连接变成无人消费的空转，只能靠进设置关诊断开关或清空数据释放。
- 错误依据：`setDiagnosticsEnabled` 的注释与 ADR 0027 明确「关闭诊断开关必须
  断开 App 级连接，不留给无人消费的空转轮询」；上一批已按同一口径修复
  「清空数据后断连」（310bcfb）。删最后一辆车与清空数据的终态相同（无车、
  探针已删、没有数据源），却漏了断连。
- 证据级别：已复现（widget 用例先红后绿）。
- 触发路径：连接 OBD 读到 38% → 离页（连接保持，ADR 0027）→ 我的页删除唯一
  车辆并确认 → 连接仍连着。
- 复现：`flutter test test/widget/diagnostics_test.dart --plain-name '删除最后一辆车断开 App 级 OBD 连接'`
  — 修复前 `disconnectCalls` 为 0；修复后为 1。
- 根因：删除动作只负责通知清扫与数据失效，没有在「删除后已无车辆」这个终态
  上收尾连接。
- 修复：`runCarDeletion` 收尾后读剩余车辆；为空则
  `obdConnectionControllerProvider.disconnectManually()`，然后再 bump 车辆
  数据纪元。删除非最后一辆车不断连（提醒页会把剩余车的探针推给连接，行为
  正常）。
- 回归：`flutter test test/widget/diagnostics_test.dart test/widget/app_shell_test.dart test/widget/vehicles_test.dart`
  60 用例全部通过。
- 文档：`docs/operations-manual.md` 5.1.3 删除车辆流程补断连收尾。
- 提交：79ba2a0

### 3. 备份恢复放行空白品牌/车型

- 位置：`lib/data/repositories/backup_repository.dart:490`
- 症状：恢复一份把车辆 `brand`/`model` 改成空白的备份会成功；我的页车辆卡
  显示空白名称，编辑表单的品牌车型是只读身份字段，用户无法修复，只能删除。
- 错误依据：手工建车只能从车型目录选择；目录外「自定义输入…」也要求品牌/
  车型两个输入框都非空（`lib/features/shell/profile/vehicle_model_picker.dart:316`
  「自定义车型弹窗：品牌/车型两个必填输入框」）。`Car` 实体本身没有 validate，
  数据库也没有非空约束，备份业务校验注释承诺「与手工录入走同一套规则」，
  却只校了容积、里程与项目。
- 证据级别：已复现（数据层用例先红后绿）。
- 触发路径：裸插一辆 `brand:' '`、`model:' '` 的车（模拟被篡改/损坏的备份
  来源）并给它一个启用项目（避开其它预校验）→ 导出 → 恢复 → 事务清库重插，
  空白身份进库。
- 复现：`flutter test test/data/backup_restore_test.dart --plain-name 'blank brand or model'`
  — 修复前恢复成功；修复后抛 typed。
- 根因：`_validateBackupBusinessRules` 的车辆循环缺少身份字段非空检查。
- 修复：车辆循环最前面补 `if (car.brand.trim().isEmpty || car.model.trim().isEmpty)
  throw ArgumentError('品牌和车型不能为空')`，沿用循环的 `try/on ArgumentError →
  LunioErrorException(backupInvalidData)` 包装；方法 doc 同步为「车辆校品牌/
  车型非空、容积与里程」。
- 回归：`flutter test test/data/backup_restore_test.dart` 22 用例全部通过。
- 提交：2809543
