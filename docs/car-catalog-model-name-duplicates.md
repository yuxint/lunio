# 已决策：车型目录中"带后缀车型"与"裸名车型"并存的问题

状态：**已决策**（2026-09-01，见 `docs/adr/0003`）
相关：`car_library/README.md`、`car_library/build_catalog.py`、`assets/data/catalog/`

## 问题是什么

懂车帝在售库并入车型目录后，部分品牌下同一车系会出现两条可选车型，例如
吉利汽车下同时存在：

- `帝豪（燃油版）` —— 老目录精选条目
- `帝豪` —— 懂车帝抓取条目

`星越 L` 更典型：目录里有 `星越 L（燃油版）`、`星越 L（混动版）`、`星越 L` 三条。
用户在新增车辆向导的选择器里会看到这类"疑似重复"。

## 为什么会这样

两份数据的粒度不同，合并时按 `(品牌 + 车型名)` 精确查重，零冲突，所以都保留了：

| 来源 | 车型命名粒度 | 默认保养模板 |
|---|---|---|
| 老目录精选（191 条） | 一个车系按动力拆成 `xx（燃油版）/（混动版）/（纯电版）` | 人工指定，动力类型精确 |
| 懂车帝抓取（1638 条） | 一个车系一条，用懂车帝原始名 | 按品牌名单 + 车名关键词推断 |

保留老条目是为了保住人工校过的模板精度；保留抓取条目是因为它是懂车帝的
原始命名，重新抓取更新目录时以它为准。

## 影响范围

只涉及老目录精选条目覆盖到的品牌（15 个改名品牌 + 本田/丰田等沿用原名的
品牌），共 191 条老条目。其余 1600+ 抓取条目无此问题。实际后果：用户若选了
`星越 L` 这类裸名条目而实际车是混动/纯电版，默认保养项目会按燃油模板给
（多出机油机滤等），需要手动删；选带后缀的条目无此问题。

## 候选方案

1. **保持现状（当前采用）**：两者都留。数据不丢、模板精度保留；代价是选择器里看起来冗余。
2. **老条目优先收敛**：老目录的带后缀条目已覆盖同一车系时，删掉对应的抓取裸名条目
   （如存在 `星越 L（燃油版）`+`星越 L（混动版）` 则不再保留 `星越 L`）。
   选择器更干净，但裸名没了，且"覆盖"判断需要按车系名归一化（去括号后缀），
   规则要在 `build_catalog.py` 里固化。
3. **反向收敛**：删老条目、只留抓取裸名。选择器最干净，但丢失人工模板精度，不建议。

## 备注

- 车辆表里已添加过的车不受此问题影响（存的是添加当时的名字）。
- 若采用方案 2，改动点只有 `car_library/build_catalog.py` 的去重规则 +
  重新生成 + 同步更新 `test/data/database_test.dart` 里的目录断言。

## 决议（2026-09-01）

采用方案 3 的修订版，完整决定见 `docs/adr/0003`，要点：

- 目录条目名以懂车帝原始车系名为准，不合并、不去前缀、不去动力词。
- 老目录 191 条全部废弃，懂车帝是目录唯一来源；覆盖不到的车型走选择器"自定义车型"手输。
- 动力类型由用户添加车辆时选择（燃油/混动/插混/增程/纯电），默认保养模板按动力类型取，
  车辆表新增动力类型字段，备份契约升 v4。
- 停售车系进目录（海外/进口标记、纯英文名、4 条欧洲未入华中文名条目排除，余 30 条），
  未上市不进。目录共 1675 条（在售 1645 + 停售 30）。
- 2026-09-01 起目录精简为每品牌最多 10 款热门车型，共 1223 条；本文其余分析基于精简前的 1675 条版本。
