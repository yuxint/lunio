# car_obd_link

通过 BLE OBD 适配器读取车辆数据，由本地 iOS App 展示。当前阶段：**硬件已验收，准备开始 App 开发**。

车型：东风本田十一代思域 2022 款 240TURBO（中国）。硬件：Vgate iCar Pro BLE 4.0。资料整理日期：2026 年 11 月 12 日。

## 1. 当前结论

2026 年 11 月 12 日完成实车验证。`012F` 返回 `41 2F 60`，油量 = 96 × 100 / 255 = **37.6471 %**。硬件保留，进入 App 开发。

| 项 | 值 |
|---|---|
| BLE Service | `000018F0-0000-1000-8000-00805F9B34FB` |
| Notify / Write | `00002AF0-...` / `00002AF1-...`（完整 UUID 见开发依据） |
| 写入方式 | `CBCharacteristicWriteWithResponse`，每条末字节 `0D` |
| CAN 协议 | `ATSP 7`，ISO 15765-4 CAN 29 bit ID / 500 kbaud |
| 适配器固件 | `ELM327 v2.3` |
| 初始化序列 | `ATZ` → `ATE0` → `ATL0` → `ATSP 7` → `012F` |
| 油量换算 | `41 2F xx` → `xx × 100 / 255`，单位 % |
| 油箱容量 | 可配置项，默认 47 L；升数标为估算 |

## 3. 实测数据

三份原始数据放在 `data/`，说明见 [data/README.md](data/README.md)。

- `IOS-Vlink.txt`：nRF Connect 导出的完整 BLE 日志，28 条命令的原始响应。**开发依据的全部结论来自这份文件**。
- `CarScanner-20261112.csv`：Car Scanner 导出的传感器时间序列，用于反推 `41 2F 60`。
- `exported_records.zip`：用户原始压缩包，内含上份 CSV 的原始文件名。

两份数据互补：CSV 反推字节，TXT 证实反推。CSV 中的 50 L 是 App 设定值，官方手册为 47 L。

## 4. 开发起点

最小链路：

1. `CoreBluetooth` 扫描并连接设备名 `IOS-Vlink`，发现 Service `18F0`。
2. 订阅 `2AF0` 通知，向 `2AF1` 写入命令。
3. 逐条发初始化序列，每条等 `>` 再发下一条。
4. 按 1–5 秒轮询 `012F`。
5. 缓冲响应字节到 `>`，解析 `41 2F xx`，换算百分比。

四个已知约束，详见[开发依据第 3 节](docs/实测结果与自研App开发依据.md)：

- **响应按 `>` 组帧**。BLE 通知会分片，`012F` 的返回分成 `41 2F 60 \r` 与 `\r>` 两次，间隔 209 ms。不能按单次通知解析。
- **同一请求可能有多 ECU 响应**。`0100` 返回三个 `41 00 ...`，解析要按 PID 匹配。
- **必须显式 `ATSP 7`**。适配器当前协议 `7` 是 Car Scanner 写入 EEPROM 的记忆，换车或复位后失效。
- **车辆电源 ON 或发动机运行**才有实时数据。熄火后、远程场景读不到。

建议第一步：把传输层抽象成协议（生产用 `CoreBluetooth`，调试用 TCP 或 Mock），用 `data/IOS-Vlink.txt` 作离线 fixture 先写 AT 状态机与解析层，再用真机验 BLE 链路。iOS Simulator 没有蓝牙。

## 5. 待验证

1. 加油前后 `012F` 数值是否跟随变化。
2. 数值去抖、跳变过滤、加油检测。
3. 熄火后重连、后台保活、断连恢复。
4. 自动协议探测能否稳定读到 `012F`。
5. 本田私有 DID `227029` 的位偏移与缩放标定。三条私有 DID 已确认有正响应，但当前需求不需要。
