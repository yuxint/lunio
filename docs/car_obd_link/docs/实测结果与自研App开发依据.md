# 实测结果与自研 App 开发依据

车型：十一代思域 2022 款 240TURBO。硬件：Vgate iCar Pro BLE 4.0。实测日期：2026 年 11 月 12 日。日志文件：`IOS-Vlink.txt`（nRF Connect 导出，173 行，28 条命令，19:25:12–19:32:14）。

<hr style="border:0;border-top:1px solid #888;margin:10px 0 18px;">

## 1. 结论

**验收通过，保留硬件，进入本地 App 开发。**

`012F` 实测返回 `41 2F 60`。此前由 Car Scanner 导出数据反推的字节 `0x60` 得到证实。油量 = 96 × 100 / 255 = **37.6471 %**。按官方手册 47 L 换算约 17.6941 L。

自研 App 所需的四项依据已齐：GATT UUID、CAN 协议号、初始化序列、响应字节格式。

## 2. 开发可直接使用的参数

| 项 | 值 |
|---|---|
| BLE Service | `000018F0-0000-1000-8000-00805F9B34FB` |
| Notify characteristic | `00002AF0-0000-1000-8000-00805F9B34FB` |
| Write characteristic | `00002AF1-0000-1000-8000-00805F9B34FB` |
| 写入类型 | `CBCharacteristicWriteWithResponse`（实测成功） |
| 命令结束符 | CR `0D`，每条单独写，等 `>` 再发下一条 |
| 当前 CAN 协议 | `ATDPN` 返回 `7`，即手动指定 ISO 15765-4 CAN 29 bit ID / 500 kbaud |
| 适配器固件 | `ELM327 v2.3`（`ATZ` 与 `ATI` 一致） |
| OBD 口电压 | 11.2 V（`ATRV`，点火 ON 未启动） |
| 油量命令 | `012F` → 写入 Hex `303132460D` |
| 油量响应 | `41 2F xx` → `xx × 100 / 255`，单位 % |
| 油箱容量 | 可配置项，默认 47 L。升数标为估算 |

**初始化序列（自研 App 必须显式执行，不得依赖 EEPROM 记忆）**

```text
ATZ
ATE0
ATL0
ATSP 7
012F
```

`ATSP 7` 不得省略。日志中 `ATSP 0` 与 `ATD` 复位协议后发的四条 PID 全部返回 `NO DATA`，见第 6 节。

## 3. 自研 App 必须处理的四个协议细节

1. **按 `>` 组帧，不要按单次 BLE 通知解析。** `012F` 的响应分成两次通知：`41 2F 60 \r`（19:28:22.758）与 `\r>`（19:28:22.967），间隔 209 ms。`0100` 同样是三帧数据后跟一个独立的 `\r>`。解析层需缓冲字节，直到收到 `3E` 才提交一次完整响应。
2. **多 ECU 响应。** `0100` 返回三个 `41 00 ...`；`010C` 返回三个 `41 0C 00 00`。同一请求可能收到多个 ECU 的回答，解析时按 PID 匹配，不能假设只有一帧。
3. **多帧与帧编号。** 私有 DID `227029` 的响应按 `0:` 到 `8:` 分成 9 行，含 ISO-TP 帧序号。当前只读 `012F` 不需要这部分，若将来接私有 DID 必须实现组包。
4. **回显与换行状态。** `ATE0` 生效后不发命令副本；`ATD` 会把回显恢复为开启，日志中 `0103\r` 即为回显。初始化序列里 `ATE0` / `ATL0` 必须排在 `ATZ` 之后。

## 5. 私有 DID：车上有升数，但暂不使用

三条本田私有 DID 在 29-bit 物理寻址下均返回 `0x62` 正响应，此前标注的「中国版未验证」已解除。

`227029` 的重组数据中存在多个除以 100 后落在 16.95–18.43 L 的 16 位大端值：

| 字节偏移 | 原始值 | ÷ 100 | 对照 |
|---|---|---|---|
| 13 | `06 CF` = 1743 | 17.43 L | 接近按 47 L 换算的 17.69 L |
| 15 | `07 33` = 1843 | 18.43 L | OBDb `CIVIC_FLV` 的 `bix:96` 跳过 `62 70 29` 响应头后落在此处 |
| 17 | `06 9F` = 1695 | 16.95 L | — |
| 19 | `06 CF` = 1743 | 17.43 L | — |

这些值与 37.6471 % 换算出的 17.69 L 同量级，说明该 DID 确实携带油量升数。但 OBDb 定义来自北美车，位偏移与缩放未经多点标定，**不能直接用于显示**。当前需求用标准 `012F` 已满足。若将来要精确升数，需在加满与低油量两点各采一次样本确认位偏移。

## 6. 本次不采信的结果

- **表 5 四条 `NO DATA` 无效。** `0103` / `0151` / `0152` / `0123` 是在 `ATSP 0`（19:31:36）与 `ATD`（19:31:43）把协议复位之后发送的，19:31:53 起全部返回 `NO DATA`。这不能推出车辆不支持这些 PID。需要数据时，重新发 `ATSP 7` 后再测。
- **四条命令日志里没有响应记录**：`ATL0`、`0120`、`015E`、`ATH1`。四条写入 Hex 都带 `0D`，写入事件也完整，原因未确认。需要这些数据时单独重发。
- `ATDPN` 返回 `7` 来自 19:18 的另一份截图日志，不在本次 `IOS-Vlink.txt` 内。

## 7. 仍未验证

1. 油量数值是否随加油变化。全部实测只在单一油量点（`0x60`）完成。
2. 数值去抖、跳变过滤、加油检测。
3. 熄火后重连、后台保活、断连恢复。
4. `ATSP 7` 之外，自动协议探测能否稳定读到 `012F`。
5. 私有 DID 的位偏移与缩放标定。

建议在加油前后各采一次 `012F`，确认数值跟随变化且无异常跳变。
